# 実験設計 — 何と何を比べて、何を主張するか

**このファイルは実装仕様であると同時に、研究の設計文書である。**
ここで決めたことは**イベント当日を過ぎると取り返しがつかない**。

推薦の中身（[04-strategies.md](04-strategies.md)）が「何を薦めるか」を決めるのに対し、
本ファイルは「**薦めた結果から何が言えるようにするか**」を決める。

## 1. 答えたい問いと、答えられる範囲

| # | 問い | 答えられるか | 使う比較 |
|---|---|---|---|
| Q1 | **周遊は促進されたか** | ✅ 記述的に言える | 去年との訪問ブース数の分布比較 |
| Q2 | **DRSA は素朴な推薦より良いか** | ✅ **因果として言える** | **参加者内ランダム化**（§2） |
| Q3 | セレンディピティは起きたか | △ 記述にとどめる | `interest_match` 別のファネル |
| Q4 | 推薦すること自体に意味があるか | ❌ **言えない** | 全員が何らかの推薦を受けるため対照群が無い |

**Q2 が本研究の中核である。** ラフ集合による推薦が、単純な逆張り推薦（COVERAGE）より
優れているか。これがきれいに言えれば研究として成立する。

**Q4 を無理に主張しないこと。** カード外訪問（自発訪問）を対照群に使いたくなるが、
カードを無視して歩く参加者とカードに従う参加者は**元から別の性質を持つ**（選択バイアス）。
カード外訪問は Q3 の参考値としてのみ使う。

## 2. 参加者内ランダム化（Q2 の設計）

### 2.1 なぜ参加者間の比較ではだめか

フェーズは決定表の件数で決まり、決定表の件数は時刻とともに増える。したがって

```
11時来場 → COVERAGE     ┐
13時来場 → SIMILARITY   ├─ フェーズ ＝ 来場時刻 ＝ 参加者の性質
15時来場 → DRSA         ┘
```

**「DRSA 群のほうが良かった」は「午後に来た人はもともと違う」と区別できない。**
フェーズと来場時刻が完全に交絡している。

去年は「推薦マスが中央4マス固定」だったため推薦効果と位置効果が交絡していた。
今年その交絡は構造的に消えたが、**代わりにこの交絡が入っている。**

### 2.2 設計 — 1回の解放を戦略で分割する

解放では 2 / 4 / 6 マスが**同時に**開く。この枠を2つの戦略で分け合う。

```
3回目の解放（6マス同時）

  枠1 ← DRSA        枠2 ← COVERAGE
  枠3 ← DRSA        枠4 ← COVERAGE
  枠5 ← DRSA        枠6 ← COVERAGE

  どの枠がどちらかは参加者に見えない（表示は同一）
```

| 解放 | 枠数 | DRSA | COVERAGE |
|---|---:|---:|---:|
| 1回目 | 2 | 1 | 1 |
| 2回目 | 4 | 2 | 2 |
| 3回目 | 6 | 3 | 3 |

**同一人物・同一時刻・同一カードの中での比較**になるので、
来場時刻・参加者の性質・会場の状況がすべて統制される。**違うのはアルゴリズムだけ。**

### 2.3 発動条件 — DRSA が本格稼働してからのみ

**COVERAGE / SIMILARITY フェーズでは分割しない。**

規則がまだ無い段階では DRSA 枠の中身が COVERAGE へ退避するため、
比較にならない枠を消費して**少ない標本をさらに削るだけ**である。

```
分割を開始する条件 ＝ DRSA の品質ゲートを通過していること
                     （03-phases.md §3.3）
```

品質ゲートは「決定表の件数」だけでなく「規則が実際に出ているか」を見る。
**件数だけで昇格させると、規則ゼロのまま分割が始まる。**

### 2.4 母集団が限定されることについて

分割の対象は「DRSA 期に解放を受けた参加者」＝実質「午後に来場した参加者」になる。

**これは制限であって欠陥ではない。** 両方の群が同じ参加者から出てくるので、
因果の主張は保たれる。弱まるのは一般化の範囲だけである。

> 論文には**適用範囲**として明記する。
> 「本研究の知見は、推薦システムが十分なデータを蓄積した後の時間帯に
> 来場した参加者について成立する」

### 2.5 実装 — 契約を変えずに実現できる

`attributes` は**ブースごとに**保存され、サーバーは中身を解釈しない。
したがって「このブースをどちらの戦略が選んだか」をここに書けばよい。

```jsonc
"attributes": {
  "v": 1,
  "strategy": "DRSA",           // ← この枠を選んだ戦略。これが実験の割付
  "arm": "DRSA",                // 明示的な実験群ラベル
  "split_seed": "…",            // 割付の再現に使う
  "condition": { … }
}
```

**サーバー・フロント・DB の変更は一切不要である。**

- 割付は `hash(user_id, unlock_event 文脈)` を種にする。**再現可能**であること
- `assigned` に渡す順序に意味は無い（サーバーは position 順に配る）ので、
  **どのマスに載るかは統制できない。統制するのは「どちらの戦略が選んだか」だけ**
- 分割時、各戦略は**自分の枠数ぶんだけ**上位を取る。
  両者が同じブースを選んだ場合は先に確定したほうが取り、他方は次点へ送る

## 3. 標本サイズと検出力

去年の実測からの外挿。**精密な推定ではなく桁感である。**

| 項目 | 概算 | 根拠 |
|---|---:|---|
| 参加者 | 150〜200 | 去年金曜 192名 |
| DRSA 期に到達する参加者 | **100〜120** | フェーズ試算（[03-phases.md](03-phases.md) §4） |
| 1人あたり分割枠 | 12（各群6） | 解放 2+4+6 |
| **各群の提示枠** | **600〜700** | 上記の積 |
| 1人あたり推薦マスへの訪問 | 中央値2件程度 | 訪問中央値6 − 中央4マス |
| 各群の訪問件数 | 100前後 | — |

**検出できる差の目安**

- **8ポイント程度の差なら検出できる**（去年の「推薦マス vs ランダムマス」が +8.4pt）
- **3〜5ポイントの差は検出できない**

したがって主張は「差があるか」の水準に留める。効果量の精密な推定はしない。
**この制約は事前に分かっているので、論文の書き方を先に決められる。**

### セレンディピティ（Q3）の標本

| 段階 | 概算 |
|---|---:|
| MISMATCH で推薦された枠（分母） | 約 600 |
| うち訪問 | 約 100 |
| うち評価が付く（36〜50%） | **約 40** |

**分子は数十件のオーダーである。** サブグループ解析（年代別 × フェーズ別など）は成立しない。
**事例の質を厚く見せる**方向で設計する（[10-observability.md](10-observability.md) の個票）。

## 4. 去年データの使い方

**去年データは対照群にならない。** 推薦アルゴリズム以外が変わりすぎている。

| 変わったもの | 去年 | 今年 |
|---|---|---|
| **ビンゴの仕組み** | 16マスを最初に全部配る | **中央4マスから段階的に開放** |
| 推薦のタイミング | 初回ログイン時に1回 | 解放のたびに最大3回 |
| 推薦マスの位置 | 中央4マス固定 | 参加者ごとに違う |
| **評価機能** | **存在しない** | 星4段階 |
| ブース | 40件（別の出展者） | 別構成 |
| 開催 | 2日間 | 1日 |

「今年は推薦マスへの訪問率が上がった」と言っても、
**「後出し方式にしたからでは?」で崩れる。** 仕組みの変更が最大の交絡である。

さらに**去年はブース単位の評価が1件も存在しない**ため、
セレンディピティ指標そのものを去年について計算できない。

### それでも有効な4つの用途

| # | 用途 | 備考 |
|---|---|---|
| ① | **Q1（周遊促進）の比較** | 仕組みの変更込みで評価するのが正しいので、これは正当 |
| ② | **自発訪問での不一致率の基準値** | 去年の40ブースに**手作業でカテゴリを付ける**と算出できる（§4.1） |
| ③ | **先行研究の限界の提示** | 去年も同じカード内比較をして +8.4pt を得たが、位置効果と分離できなかった。**今年はそれを構造的に解決した**という筋書き |
| ④ | しきい値決定のためのシミュレーション | 「DRSA は何時に発火するか」の事前確認 |

### 4.1 去年ブースへのカテゴリ付与（②の前提）

去年のデータには参加者の興味ジャンル（8区分・単一選択）はあるが、
**ブース側にカテゴリが無い**ため突き合わせができない。ブースは40件なので手作業で付与できる。

**手順の制約（バイアス防止）**

- **今年のカテゴリが確定してから行う**（分類体系を揃えるため）
- **結果を見る前に付与を完了させる。** 結果を見てから分類を調整しない
- 付与規則を文書化し、可能なら複数人で独立に付けて一致率を確認する

**限界**: 去年は評価が無いので「行った」までしか言えず「気に入った」は言えない。
また去年の興味ジャンルは単一選択、今年は複数選択なので定義を揃える工夫が要る。

### 4.2 去年データの再解析（可能性・要検証）

去年の枠数は `推薦マス 912 / ランダムマス 3,776 / 合計 4,688`（293名 × 16マス）。
推薦マスは1人4枠なので **912 ÷ 4 = 228名**。つまり **293名中65名は中央4マスもランダム**
だった可能性がある（フォールバック解除 11:34 より前にカードを作った層）。

もしそうなら、**位置を固定したまま推薦の有無だけを比較できる**かもしれない。
ただし**この65名は「朝早く来た人」なので、今年と同じ時刻の交絡が入る。**
完全には解決しない。

> **上記の 228 / 65 は合計値からの推測である。実データでの検証が必要。**

## 5. 事前に凍結すること（分析の事前登録）

**イベント前に紙に書いて固定する。事後に決めると、都合のよい結果を選んだことになる。**
コストはほぼゼロで、研究の信頼性への効果が大きい。

| 凍結する項目 | 例 |
|---|---|
| 主要な結果指標 | 「推薦枠への訪問率」を主要指標とする |
| 比較の方法 | 参加者ごとの差の分布。対応のある検定 |
| 除外規則 | `role <> 'participant'` を除外。他に除外しない |
| セレンディピティの定義 | `interest_match = MISMATCH` かつ訪問かつ高評価 |
| 高評価の定義 | `normalized >= 0.75` |
| 副次的な分析 | **副次であると明記する**（主要指標と同列に扱わない） |

## 6. やってはいけないこと

| # | 禁止 | 理由 |
|---|---|---|
| R-1 | **当日に A/B の効果（訪問率の差）を見る** | 見ると設定を変えたくなる。**途中で条件を変えたデータは比較できない。** 当日は分母（提示数）だけ見る（[10-observability.md](10-observability.md)） |
| R-2 | 当日にしきい値・重みを、結果を見て変更する | 同上。変更する場合は**変更時刻を記録し、前後を別データとして扱う** |
| R-3 | 規則が出ないからといって品質ゲートを下げる | **去年の失敗（解除が早すぎた）の再現**。出ないなら出ないと報告する |
| R-4 | 事後に指標の定義を変えて有意になるものを探す | §5 の凍結に反する |
| R-5 | Q4（推薦自体の効果）を主張する | 対照群が無い |
