# ADR 0001 — DRSA を自前実装する

- **状態:** 採用
- **日付:** 2026-08-29

## 背景

推薦の中核に DRSA（Dominance-based Rough Set Approach）を使うことが決まっている。
既存ライブラリを使うか、自前で実装するかを決める必要がある。

**DRSA は通常のラフ集合（識別不能関係ベース）とは別物である。**
順序尺度の属性を優越関係で扱う手法であり、ライブラリの選定でここを取り違えると
まったく違うものを実装することになる。

## 調査した候補

| 候補 | 言語 | 判定 |
|---|---|---|
| [`roughsets-base`](https://github.com/darekjk/roughsets-base) | Python | ❌ **古典ラフ集合。DRSA ではない**。優越関係を扱えない |
| [`roughset`](https://pypi.org/project/roughset/0.2.0) | Python | ❌ 同上。非順序の reduct とルール抽出 |
| `scikit-roughsets` / [`fuzzy-rough-learn`](https://link.springer.com/chapter/10.1007/978-3-030-52705-1_36) | Python | ❌ 特徴選択・ファジィラフ。DRSA ではない |
| [`gis-drsa`](https://github.com/gmassei/gis-drsa) | Python | △ DOMLEM の実装はあるが **QGIS/GRASS プラグインに結合**しており、ライブラリとして切り出されていない |
| [jMAF / jRS](https://link.springer.com/chapter/10.1007/978-3-642-30344-9_5) | Java | △ DRSA の本家格だが**別プロセスが必要**。1000ms のタイムアウト予算に挟みたくない |
| [`RoughSets`](https://cran.r-project.org/package=RoughSets) | R | △ 同上（言語が違う） |

**使える Python の DRSA 実装は事実上存在しない。**

## 決定

**自前実装する。** `drsa/` パッケージに、優越関係・近似・規則生成を実装する。

## 理由

「無いから」だけではない。**規模が小さいことが決め手である。**

- 条件属性 **2〜3個**、各 **3〜4値**（[02-features.md](../../specs/02-features.md)）
- 決定クラスは **2値**（HIGH / LOW）
- 決定表は最大でも**数百行**

この規模なら、優越集合・上下近似・境界領域・規則生成は数百行で書け、
**全パターンを手計算と突き合わせてテストできる**（[05-drsa.md](../../specs/05-drsa.md) §6）。

さらに積極的な理由が2つある。

1. **正本が「DRSA を説明可能な選択フィルタとして使う。精度最大化の予測器ではない」と定めている。**
   研究発表で「なぜこのブースを薦めたか」を説明する必要がある以上、
   **内部が見えることに価値がある。** ライブラリで隠すと説明の負債になる
2. **可変一貫性版（VC-DRSA）が必須である。** 厳密な下方近似は本件のデータではほぼ空集合になり、
   規則が1本も出ない。一貫性水準を外から調整できる必要があり、
   これはライブラリの対応状況に依存したくない部分である

## 結果・トレードオフ

- **利点:** 依存が減る（`numpy` / `pandas` 程度）。挙動を完全に把握できる。決定性を保証できる
- **欠点:** 正統的な DOMLEM ではなく**全列挙**を採る（探索空間が極小のため）。
  属性を増やして探索空間が爆発する構成に変えるときは、この判断を見直すこと。
  目安は条件の候補が 10,000 を超えたとき
- **欠点:** 手法の正しさを自分で担保する必要がある。
  → 手計算できる決定表での検証をテストに固定する（[07-testing.md](../../specs/07-testing.md) §5）
