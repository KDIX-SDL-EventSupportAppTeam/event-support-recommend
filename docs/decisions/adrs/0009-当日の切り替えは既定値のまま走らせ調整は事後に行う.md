# ADR 0009 — 当日の戦略切り替えは既定値のまま走らせ、パラメータ調整は事後に行う

- **状態:** 採用
- **日付:** 2026-09-01
- **関連:** [ADR 0002](0002-決定表のデータ入手経路.md)、[ADR 0003](0003-条件属性の構成.md)、[ADR 0007](0007-戦略の選択を環境変数で行う.md)

## 背景

[ADR 0002](0002-決定表のデータ入手経路.md) が決着し、段3・段4（`SIMILARITY` / `DRSA` の結線）に
着手できるようになった。しかし `docs/README.md` の「未決定事項の一覧」には、
値が確定していない項目が **9件** 残っている。

| 出典 | 未決定の項目 | 現在の既定値 |
|---|---|---|
| [03-phases](../../specs/03-phases.md) | `PHASE_SIMILARITY_MIN` | 30（**根拠が弱いと明記済み**） |
| [03-phases](../../specs/03-phases.md) | `PHASE_DRSA_MIN` | 60（条件属性2個 → 4×3=12 パターン × 各5件） |
| [09 RD-2](../../specs/09-research-design.md) | 品質ゲート（規則3本・γ 0.5・被覆率 0.5） | 3 / 0.5 / 0.5 |
| [05-drsa D-1](../../specs/05-drsa.md) | `DRSA_CONSISTENCY` | 0.8 |
| [02-features F-1](../../specs/02-features.md) | `exploration_disposition` を有効化するか | 無効（属性2個） |
| [02-features F-3](../../specs/02-features.md) | `booth_tags` を使うか | 使わない |
| [04-strategies T-1](../../specs/04-strategies.md) | `MAX_PER_CATEGORY` | 0（無効） |
| [09 RD-1](../../specs/09-research-design.md) | 参加者内ランダム化を実施するか | 未実施 |
| [ADR 0007](0007-戦略の選択を環境変数で行う.md) | `RANDOM` の性質 | ADR の明文どおり P-6 優先 |

**これらを全部決めてから実装を始めると、本番（2026-10-16）に間に合わない。**

## 決定

**現状の既定値のまま実装し、当日はその値で走らせる。細かい調整は事後に行う。**

- 段3・段4 の実装は、上記9件の決着を**待たない**
- 当日、値を変えるための操作は行わない（**触らないことを既定とする**）
- 値の妥当性の検証・調整は、イベント後のデータを使って行う

## 理由

- **既定値はすべて根拠つきで書かれており、「適当な値」ではない。**
  弱い根拠のものは「根拠が弱い」と明記されている（`PHASE_SIMILARITY_MIN=30`）。
  未検証であることと、無根拠であることは違う
- **調整の材料が今は存在しない。** 去年のデータには評価が無いため、しきい値も近傍の重みも
  事前には検証できない（[04-strategies T-2](../../specs/04-strategies.md)）。
  つまり「決めてから実装する」は、実際には「決められないまま止まる」ことを意味する
- **当日いじると研究データが壊れる。** 途中でパラメータを変えると、前半と後半で
  別のアルゴリズムが走ったことになり、比較の土台が消える
- 退避（degradation）が設計に組み込まれているため、**値が不適切でも壊れない。**
  規則が出なければ SIMILARITY へ、近傍が作れなければ COVERAGE へ静かに落ちる

## 「起きてはいけないこと」

- **当日、しきい値やパラメータを変更してリビジョンを差し替えること。**
  障害対応（推薦が明らかに壊れている）を除き、行わない。
  行った場合は必ず時刻を記録し、事後分析でその前後を分けて扱う
- **既定値を「確定値」として仕様書に書き換えること。** 暫定は暫定のまま残す
  （[rules/documentation.md](../../rules/documentation.md) §4）

## 影響

- `docs/README.md` の「未決定事項の一覧」は**そのまま残す**。決めたのは
  「今回は既定値で走らせる」ことであって、値そのものではない
- 事後分析（`event-support-analytics` の `post_analysis`）に、
  **各パラメータの妥当性検証**を課題として引き継ぐ
- 当日の運用手引きに「パラメータは触らない」を明記する
