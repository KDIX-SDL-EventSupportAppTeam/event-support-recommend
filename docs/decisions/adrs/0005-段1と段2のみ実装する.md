# ADR 0005 — 実装は段1（COVERAGE ＋ features/）と段2（drsa/ コア）に限る

- **状態:** 採用
- **日付:** 2026-08-30

## 背景

仕様（[docs/README.md](../../README.md)）は一通り揃ったが、
[ADR 0002](0002-決定表のデータ入手経路.md)（決定表のデータ入手経路）が**未決定**である。
[08-architecture.md](../../specs/08-architecture.md) §6 の実装順序は次のとおり。

| 段 | 内容 | ADR 0002 の決着 |
|---|---|:-:|
| 1 | スケルトン ＋ `COVERAGE` ＋ `features/` | 不要 |
| 2 | `drsa/`（純粋部分）とテスト | 不要 |
| 3 | `data/`（スナップショット取得）＋ 規則キャッシュ | **必要** |
| 4 | `SIMILARITY` / `DRSA` の結線 | **必要** |

## 決定

**段1と段2のみを実装する。段3・段4には着手しない。**

- `data/repository.py` はインターフェースと `UnavailableRepository`（常に「取得不能」）だけ
- `cache/rule_cache.py` は受け皿のみ。バックグラウンドの決定表構築・規則再生成は結線しない
- リクエスト経路のフェーズ判定は動くが、スナップショットが常に「取得不能」なので
  `decision_table_size` は常に `null`、`phase` は常に `COVERAGE`
- `SIMILARITY` / `DRSA` 戦略クラスは未実装（`strategies/` は `CoverageStrategy` のみ）

## 理由

- [AGENTS.md](../../../AGENTS.md) の禁止 #6「未決定事項を勝手に決めて実装する」に反しないため
- `COVERAGE` だけでも本番投入の価値がある（[08](../../specs/08-architecture.md) §6）。
  サーバー側フォールバックは「訪問者数が少ない順」だけで、こちらは関心分野一致の一項ぶん賢い
- `drsa/` は純粋なので、合成データと手計算で完全にテストできる（[07](../../specs/07-testing.md) §5, §8.1）。
  データ入手経路が決まってから慌てて書くより、先に固めておくほうが安全

## 段3・段4へ進む条件

1. [ADR 0002](0002-決定表のデータ入手経路.md) が「採用」になり、接続情報の扱いが決まる
2. [09-research-design.md](../../specs/09-research-design.md) RD-1（参加者内ランダム化を実施するか）が決まる
   — `assignment.split_assigned()` は実装済み・テスト済みだが、
   engine からの呼び出しは品質ゲート通過時のみで、現状そこへは到達しない

## この ADR で決めていないこと（引き続き未決定）

[docs/README.md](../../README.md) の「未決定事項の一覧」はすべてそのまま。
特に 0002 / RD-1 / RD-2 / F-1〜F-3 / しきい値 30・60 / D-1 は触れていない。
