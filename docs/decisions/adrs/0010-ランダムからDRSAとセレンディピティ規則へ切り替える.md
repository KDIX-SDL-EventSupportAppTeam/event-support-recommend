# ADR 0010 — 推薦方式を「ランダム → DRSA ＋ セレンディピティ規則」へ切り替える

- **状態:** 採用（2026-10-10 にユーザー（三上）が確定）
- **日付:** 2026-10-10
- **関連:** [ADR 0007](0007-戦略の選択を環境変数で行う.md)、[ADR 0009](0009-当日の切り替えは既定値のまま走らせ調整は事後に行う.md)、
  親 issue [#37](https://github.com/KDIX-SDL-EventSupportAppTeam/event-support-recommend/issues/37)

## 背景

第4回プロトフェス（2026-10-16 金）に向け、シミュレーション（去年金曜の集計値に合わせた合成来場者を、
本番と同じコード経路に流したもの。ここで言う「シミュレーション」は 2026-10-10 のセッションで行われ、
その道具は本リポジトリに無い）を重ねて次の事実が分かった。

1. **現行設定ではラフ集合（DRSA）が解放の 0〜4% しか動かない。** 原因はデータ量ではなくゲートの作りで、
   ①確実規則を「高評価向き（上方）」だけで数えている ②一貫性の水準 0.8 が高すぎる
2. 学習用の決定表と推薦時の属性計算が **3 か所ずれている**（自発訪問の +1、低評価の範囲、未来の評価の混入）
3. **γ（近似の質）は予測力を測らない。** ★4 を付けやすい会場では偽の規則がゲートを通る
   → 規則の確信度が基準率を上回ること（**リフト条件**）が要る
4. **SIMILARITY 期は人気と正の相関になる**（順位相関 +0.21）。DRSA 期は +0.17。
   現行設定のまま `READONLY_PROXY_URL` を設定すると推薦が人気寄りになる傾向がある（去年の失敗に近い方向）
5. DRSA は「関心一致 → 高評価」を学ぶため**関心外を薦めにくい**。関心外枠が要る
6. 研究で一番主張したいのは「ラフ集合でセレンディピティが起きた」こと

## 決定

**次の構成で実装する。** 仕様の数値はすべて上記シミュレーションの結果に基づく。

### 確定した方針

| 項目 | 決定 |
|---|---|
| RD-1（参加者内ランダム化） | **実施しない。** 当日の来場者数・データ量が読めず、枠を割ると研究に足るデータが取れない恐れがあるため |
| 段階 | ゲート不通過の間は**完全ランダム**（候補ごとに独立の一様乱数。シードは user_id＋解放文脈）。通過後は **DRSA**。DRSA が使えなければ静かにランダムへ戻る。**SIMILARITY と COVERAGE（訪問者が少ない順）は自動モードで使わない** |
| 品質ゲート（RD-2） | 決定表 **≥ 60 件** ／ γ **≥ 0.5** ／ 候補の被覆率 **≥ 0.5** ／ **確信度が基準率を 0.10 以上上回る確実規則が、上方・下方合わせて 2 本以上**（基準率は上方なら全体の★4率、下方なら★1〜3率） |
| 一貫性の水準（D-1） | **0.6**（旧 0.8）。最小支持 5。高評価は **★4 のみ**。条件属性は `preference_match`・`rating_affinity` の 2 つ |
| 決定表の修正 | ずれ 3 点を直す（自発訪問 +1 を入れる・低評価は★1 のみ・その行より前の情報だけを使う） |
| ランダムの性質（ADR 0007 の未決事項） | **乱択性を採る。** 候補ごとに独立の一様乱数とし、P-6（同じ関心一致の候補は `visitor_count` 昇順）は課さない |
| マスの割り当て | 開くマスの**半分が関心外枠**（2→1、4→2、6→3）。残りは全体から点数順（同点は訪問者の少ない順 → 参加者ごとの乱数） |
| 関心外枠の 1 マスごと | **30% は探索**（関心外ブースからランダム）。**70% はまずセレンディピティ規則**で選び、当てはまる候補が無ければ**採点済みの順位**（DRSA 期は DRSA、ランダム期は乱数）で選ぶ |
| セレンディピティ規則 | 5 分ごとに**関心外ブースへの評価だけ**から作る（古典ラフ集合の等価クラス）。条件 = **第1希望 × ブースのカテゴリ**、結果 = ★4 か。**5 件以上・3 人以上・★4 率 ≥ 0.5・そのカテゴリ自体の★4率（全員の評価、(★4数+1)/(件数+2) で平滑化）より 0.15 以上高い**グループだけを規則にする。関心外の評価が **20 件以上**で使い始める。性別などの個人属性は使わない |
| 記録 | マスごとに `reason.strategy` を **RANDOM / DRSA / SER（規則）/ EXPLORE（探索）** で残す。SER は該当規則も残す。契約の `phase` は 3 値なので、ランダム期は `COVERAGE` を返す |
| 運用への依頼（本リポジトリ外） | 推薦マスでの評価を必須（ワンタップ・スキップ付き・スキップを記録）にする。事前アンケートのキー名 `interest_categories`・`top_interest_category` を一致させる |

### 設定値

`drsa_min_lift=0.10`、`drsa_consistency 0.8→0.6`、`drsa_min_rules 3→2`、`mm_quota=0.5`、`explore_rate=0.3`、
`ser_min_rows=20`・`ser_smin=5`・`ser_min_persons=3`・`ser_lift=0.15`・`ser_min_p=0.5`。
`phase_similarity_min`・`phase_drsa_min`（60）は変えない（`phase_similarity_min` は自動モードでは使われなくなる）。

## 理由

- **安全**: リフト条件で誤作動（好みの差が一切無い世界でラフ集合が動く割合）を 3〜4% に抑え、
  推薦が特定ブースに集中しない（上位 5 ブースの割合はランダム 15% に対し 18%）
- **案 1 を選び案 2 を選ばない理由**: 案 2（切替 40 件・一貫性 0.55・リフト 0.08）はラフ集合の担当が多い（約 77%）が、
  好みの差が無い世界での誤作動が 4〜7% で上限（5%）に近い。余裕が小さいので安全側を取る
- **セレンディピティ規則を足す理由**: 研究の主張に、規則そのもの（「第1希望が AI の人は関心外のものづくりを意外と高評価」）で答えられる。
  規則で選んだ関心外は探索の関心外より★4 確率が約 +0.1 高い
- **規則の無い枠を DRSA の順位で埋める理由**: ランダムで埋めると「ラフ集合が選んだ関心外推薦」が減り、
  研究データが 1 日 3〜6 件に落ちる。DRSA で埋めると 27.7 件/日（評価必須時）
- **探索 30% を残す理由**: 自己強化（規則で薦めたものだけ評価が集まる）を防ぎ、同じ時間帯の比較群にもなる
- **年齢・性別を使わない理由**: 上乗せが最大 +0.003 と小さく、誤作動・点滅（規則の入れ替わり）・個人特定のリスクが増える
- **乱択性を採る理由**: P-6 を守ると同じクラスの中が `visitor_count` 昇順で決まり、COVERAGE と同じ反人気バイアスが残る。
  ランダム期は「対照・下限」であり、偏りを持たない乱数であるべき

## 合格基準（シミュレーションでの診断結果の要約）

探索に一度も使っていない 300 世界で、実行前に固定した基準により判定した。推奨構成は全項目合格。

| 基準 | しきい値 | 推奨構成 | （比較）現行の本番設定 |
|---|---|---|---|
| S-1 誤作動（好みの差が無い世界でラフ集合が動く割合） | ≤ 5% | 2.1〜3.1% | 0.0%（そもそも動かない） |
| S-2 上位 5 ブースへの集中（平均） | ≤ 25% | 17.8% | 21.2% |
| S-4 推薦スコアと人気の順位相関（平均） | ≤ 0.15 | +0.027 | **+0.156（不合格）** |
| R-1 ラフ集合が関わる解放 | ≥ 30% | 55〜57% | **3.7%（不合格）** |
| R-4 規則 − 探索の★4 確率差の 95%CI 下限 | > 0 | +0.074〜+0.105 | — |

当日の異常のうち、来場者が極端に少ない日（60〜100 人）・推薦をほぼ誰も見ない日・データ取得が止まる日は
研究データ量の基準を満たさない（アルゴリズムでは補えない）。取得が止まっても推薦処理のエラーは 0 件でランダムに戻る。

## 「起きてはいけないこと」

- **人気順の推薦。** ランダム期でも DRSA 期でも、スコアと訪問者数の順位相関が正に大きくならないこと
  （[07-testing §1](../../specs/07-testing.md)）
- **規則が出ないからといってゲートを下げること。** 「解除が早すぎた」という去年の失敗の再現
- **セレンディピティ規則の比較基準を全体の★4 率にすること。** 人気カテゴリを拾う（去年の失敗の再現）。
  **必ずそのカテゴリ自体の★4 率**と比べる
- **当日に設定値を変えること。** ADR 0009 を維持する（下記）
